# Онлайн-оплата в приложении — задание серверу

Для треда «Работа на сервере argeda.ru». Приложение уже готово принимать онлайн-оплату
(версия 1.6) — нужен только API. Приложение — тонкий клиент: само оно деньги не принимает,
оно открывает платёжную страницу от сервера и показывает статус. Платёж проводит тот же
провайдер (эквайринг), что и на сайте argeda.ru — отдельный договор на приложение не нужен.

## Что сделать (минимум)

1. **Включить флаг.** В `GET /config` → `"features": { ..., "online_payment": true }`. Пока он
   `false`, приложение показывает только «оплата при получении» — ничего не ломается.

2. **Создание заказа с оплатой.** В `POST /orders` приложение шлёт `"payment": "online"`
   (сейчас шлёт `"on_receipt"`). В ответ на `online` верните заказ с блоком оплаты:
   ```json
   {
     "number": "A-123", "id": "...", "status": "new",
     "payment": { "status": "pending", "url": "https://<касса>/pay/<token>", "provider": "yookassa" }
   }
   ```
   - `url` — hosted-страница оплаты провайдера (та же, что открывает сайт). Приложение откроет её
     во внешнем браузере телефона.
   - Сумму берёт **сервер** из заказа (в копейках), не из клиента.

3. **Статус оплаты.** В `GET /orders/{id}` добавьте `"payment_status": "pending" | "paid" | "failed"`
   (и сохраняйте `payment.url`, пока `pending`). Приложение раз в 5 секунд опрашивает заказ и, как
   только `paid`, показывает «Оплачено онлайн».

4. **Webhook провайдера.** Провайдер дёргает ваш серверный webhook → вы помечаете заказ `paid`.
   Обязательно: проверка подписи webhook, идемпотентность (один платёж — один раз), сумма и валюта
   сверяются с заказом. Статус заказа приложение узнаёт только из п.3 — webhook серверный.

5. **Возврат в приложение.** После оплаты провайдер редиректит на `return_url` на argeda.ru
   (страница «спасибо»). Приложение не зависит от редиректа — оно опрашивает статус. По желанию
   можно сделать deep link `ru.argeda.design://order/{id}` для автодоезда назад в приложение.

## Провайдер
Используйте тот же, что на сайте. Вы упомянули Ozon — если это **Ozon Банк эквайринг**, подойдёт
его hosted-оплата. Так же легко встанут ЮKassa, CloudPayments, Тинькофф Касса, СБП — приложению
всё равно, оно просто открывает `payment.url`. Укажите в ответе `provider`, чтобы мы понимали, что
подключено.

## 54-ФЗ (чек)
Онлайн-оплата требует фискального чека. Обычно его формирует провайдер/ОФД по данным заказа
(позиции, цены, НДС). Передавайте провайдеру состав заказа при создании платежа.

## Что уже сделано в приложении (чинить не нужно)
- Выбор способа оплаты в корзине: «Онлайн картой/СБП» или «При получении».
- Создание заказа с `payment: "online"`, открытие `payment.url` во внешнем браузере.
- Экран заказа: «Ожидает оплаты» с кнопкой «Оплатить», опрос статуса, «Оплачено онлайн».
- Пока сервер не включил `online_payment`, в боевой сборке онлайн-оплаты нет; в тестовой —
  демо-режим (кнопка «Оплатить (демо)»), чтобы видеть флоу. Реальные деньги демо не трогает.

После включения флага и п.2–4 напишите — проверю оплату из приложения на тестовом заказе.

## Обновление (приложение 1.7, после ответа сервера)

Сервер поднял оплату (Ozon Pay, online_payment: true). Приложение приведено под финальный контракт:
- В корзине, когда `online_payment: true`, онлайн-оплата выбрана **по умолчанию** (раньше по умолчанию
  было «при получении», из-за чего заказ уходил без `payment: "online"`). Кнопка «При получении»
  остаётся.
- Кнопка «Оплатить» у заказа теперь вызывает **`POST /orders/{id}/pay`** и открывает `url` из ответа
  (раньше просто открывала сохранённую ссылку, поэтому «ничего не делала»).
- Новый заказ online: `POST /orders` c `payment: "online"`, открываем `order.payment.url`; если его нет —
  сразу зовём `/pay`.
- Обрабатываем **409 `online_payment_required`**: показываем «Этот заказ можно оплатить только онлайн»,
  переключаем способ на онлайн.
- Статусы `none / pending / paid / failed / refunded` — показываются; пока `pending`, заказ опрашивается.
- Deep link **`ru.argeda.design://order/A-номер`** обрабатывается (intent-filter + singleTask):
  кнопка «Вернуться в приложение» открывает нужный заказ.

Поле способа оплаты шлём как `"payment": "online" | "on_receipt"` (как в вашем примере). Если удобнее
`payment_method` — скажите, поменяю.

## Важно: кнопка «Вернуться в приложение» должна быть intent-ссылкой

На странице «Спасибо! Проверяем оплату» кнопка сейчас, судя по поведению, ведёт обычной ссылкой
`ru.argeda.design://order/A-номер`. На Android такая ссылка **ненадёжна** — Samsung Internet и
встроенные браузеры её не открывают как приложение, а переходят по странице (возвращают на сайт).
Нужно оформить кнопку как **`intent://`** с пакетом приложения и фолбэком:

```
intent://order/A-425#Intent;scheme=ru.argeda.design;package=ru.argeda.design;S.browser_fallback_url=https%3A%2F%2Fargeda.ru%2F;end
```

- если приложение установлено — откроется нужный заказ (приложение уже обрабатывает scheme
  `ru.argeda.design`, host `order`);
- если не установлено — браузер уйдёт на `browser_fallback_url` (можно оставить страницу заказа на сайте).

Приложение, со своей стороны, при любом возврате в него (даже без нажатия кнопки) сразу обновляет
открытый заказ, так что статус «Оплачено» появляется, как только пользователь вернётся в приложение.
