## 1. Что сервер уже отдаёт (эндпоинты /api/app/v1)

### Общее
| Адрес | Что отдаёт |
|---|---|
| `GET /config` | версии приложения, ссылка на APK, пункт выдачи (адрес, часы; координат пока нет), телефон, версия согласия, возможности (`sms_login`, `online_payment`, `courier`) |
| `OPTIONS /…` | заголовки CORS для WebView приложения |
| неизвестный адрес | 404 `{"error":{"code":"not_found"}}` |

### Каталог товаров
| Адрес | Что отдаёт |
|---|---|
| `GET /catalog/categories` | дерево разделов: `id, slug, name, parent_id, count` (только непустые) |
| `GET /catalog/home` | главный экран: `banners` (популярные товары), `quick` (8 крупных разделов), `in_stock_today` |
| `GET /catalog/products` | список товаров. Параметры: `category, q, page, limit (до 100), sort`. Ответ `{items, total, page}`. **Ищет только по товарам** |
| `GET /catalog/products/{id}` | карточка: до 8 фото по 800 px, описание, характеристики, `fits` (к каким моделям подходит) |
| `GET /catalog/sync` | весь каталог кусками до 2000 товаров (`page`, `limit`, `total`, `has_more`) |

Поле товара `install_service_id` — связь запчасти с услугой установки/ремонта. В отчёте этапа 1 оно было `null`, обещано на этапе 2; заполнено ли сейчас — **уточнит серверная ветка**.

### Ремонт телефонов
| Адрес | Что отдаёт |
|---|---|
| `GET /repair/services?model=` | модель, `model_found`, список услуг ремонта: `id, problem (screen/battery/port/camera/water/other), name, price_from, duration` |
| `GET /repair/slots?date=YYYY-MM-DD` | свободное время каждые 30 минут, 10:00–20:00, на 30 дней вперёд |
| `POST /repair/bookings` | запись на ремонт → заявка в админке, номер `R-…`. Обязателен `consent_version` |
| `GET /repair/bookings` | мои записи (нужен вход) |

Модель нужно присылать названием («Samsung Galaxy A01»), а не кодом «SM-A015F». Цены «от» одинаковые для всех моделей, как на сайте.

### Вход и профиль
| Адрес | Что делает |
|---|---|
| `POST /auth/login` | телефон + пароль, как на сайте → `token` (живёт 90 дней) и `user` |
| `POST /auth/code`, `POST /auth/verify` | вход по SMS-коду — пока только в тестовом режиме (тест-номер +79990000001, код 0000); без него `501 sms_unavailable` |
| `GET /me` | данные клиента |
| `POST /auth/logout` | токен перестаёт работать |

### Заказы
| Адрес | Что делает |
|---|---|
| `POST /orders/quote` | пересчёт корзины сервером: цены, наличие, услуги, доставка (курьер 140 / 1000 / 2000 ₽), итог, предупреждения (`price_changed` и др.) |

| `GET /orders` | мои заказы (нужен вход) |
| `GET /orders/{id}` | один заказ по `id` или номеру `A-123`. Статусы: `new, in_work, ready, done, cancelled`. `pickup_code` появляется, когда заказ готов к выдаче |

## 2. Каталог услуг целиком

**Сейчас эндпоинта для всего каталога услуг нет.** Есть только `GET /repair/services?model=` — ремонт телефонов под модель.

На сайте услуги устроены так (макет `argeda/dizayn/uslugi-maket.md`, 7 направлений):
Ремонт телефонов · Ремонт техники · Спутниковое ТВ · Эфирное ТВ · Настройка и установка · Видеонаблюдение · Триколор.
Услуги внутри направления — бывшие карточки `/services/item/…` с ценой «от», сроком и гарантией. Услуги на сайте считаются товарами (`/services`), поэтому у них уже есть `id`, цена и картинка в базе.

### Предлагаю сделать `GET /services/catalog`

Один запрос, отдаёт всё дерево сразу (услуг немного, кэшировать на час):

```json
{

    {
      "id": "remont-telefonov",
      "name": "Ремонт телефонов",
      "slug": "remont",
      "icon": "phone",
      "price_from": 500,
      "services": [
        {
          "id": "cms1nsjw8000b2k8ejski3igb",
          "name": "Замена аккумулятора",
          "direction_id": "remont-telefonov",
          "price_from": 1500,
          "duration": "от 30 минут",
          "warranty": "3 месяца",
          "type": "workshop",
          "problem": "battery",
          "needs_model": true,
          "fits": { "brands": ["Apple", "Samsung"], "models": [] },
          "image": "https://argeda.ru/…webp",
          "description": "…"
        }
      ]
    },
    {
      "id": "sputnikovoe-tv",
      "name": "Спутниковое ТВ",
      "price_from": 2500,
      "services": [
        {
          "id": "…",
          "name": "Триколор под ключ",
          "direction_id": "sputnikovoe-tv",
          "price_from": 2500,
          "duration": "2–3 часа",
          "warranty": "1 год на монтаж",
          "type": "onsite",
          "needs_model": false,

            { "id": "own", "name": "Своё оборудование", "price": 0 },
            { "id": "…", "name": "Привезём наше", "price": 7990 }
          ]
        }
      ]
    }
  ],
  "updated_at": "2026-10-24T12:00:00Z"

```

Поля услуги:
| Поле | Что это |
|---|---|
| `id` | id услуги (строка, тот же, что в `/repair/services` и в корзине) |
| `name`, `description`, `image` | название, 1–2 строки описания, картинка |
| `direction_id` | направление |
| `price_from` | цена «от», в рублях, целое |
| `duration` | срок строкой, как на сайте («от 40 минут») |
| `warranty` | гарантия строкой или `null`, если на сайте не указана (у ТВ и видеонаблюдения пока не указана — не придумывать) |
| `type` | `workshop` — в мастерской / пункте приёма; `onsite` — выезд мастера на адрес; `both` — можно так и так |
| `needs_model` | нужно ли выбирать модель (ремонт телефонов — да, Триколор — нет) |
| `problem` | только для ремонта: `screen/battery/port/camera/water/other` |
| `fits` | к чему относится: `brands`, `models` (по справочнику «Модели ремонта», 624 модели), `products` (id товаров: ресиверы, антенны, камеры) |
| `equipment_options` | своё / наше оборудование с ценой, где это есть |

Дополнительно:
- `GET /services/catalog/{id}` — одна услуга с полным описанием («что входит», «что нужно от вас», вопросы).
- `/repair/services?model=` оставить как есть: он уже отдаёт цены под модель и используется для записи.
- Как оформлять выездную услугу: через корзину `POST /orders/quote` → `POST /orders` (услуга — обычный товар) или через отдельную заявку `POST /services/requests` (имя, телефон, адрес, услуга) — так работает форма «Вызвать мастера» на сайте. Что проще, **скажет серверная ветка**. Я бы сделал `/services/requests`, чтобы заявки падали туда же, куда с сайта.

Чего в базе сайта может не быть (**уточнит серверная ветка**): поле «тип» (мастерская/выезд), гарантия у части услуг, привязка услуги к товарам. Если поля нет — отдаём `null`, в приложении скрываем.

## 3. Единый поиск по товарам и услугам

`GET /catalog/products?q=` ищет **только товары**.

**Предлагаю один `GET /search?q=&type=&page=&limit=`**, а в ответе — два списка в одном ответе. Так приложению проще: один запрос на экран поиска, а вкладки «Всё / Товары / Услуги» переключаются без новых запросов.

```json
GET /search?q=замена экрана iphone 14&limit=20

{
  "q": "замена экрана iphone 14",
  "products": { "items": [ …как в /catalog/products… ], "total": 12 },
  "services": {
    "items": [
      { "id": "…", "name": "Замена дисплея смартфона", "direction": "Ремонт телефонов",
        "price_from": 1500, "duration": "от 40 минут", "type": "workshop", "image": "…" }
    ],
    "total": 2
  },
  "suggest": ["iPhone 14 дисплей", "iPhone 14 аккумулятор"]
}
```

- `type=products` или `type=services` — отдать только один список (для вкладки и подгрузки страниц).
- Элемент товара — та же карточка, что в `/catalog/products`, плюс поле `kind: "product"`; у услуги `kind: "service"`. Тогда можно и рисовать одной лентой, если захочется.
- Поиск по услугам должен понимать название модели: запрос «iPhone 14» находит и запчасти, и услуги ремонта для этой модели (через справочник моделей).
- `suggest` — подсказки, необязательно, можно позже.

Почему не два отдельных запроса: лишний сетевой запрос на каждую букву в поиске. Почему не одна смешанная лента: товаров 36 тысяч, услуг десятки — услуги утонут. Два списка в одном ответе решают обе проблемы.

На стороне сервера это один обработчик, который вызывает уже существующий поиск товаров и новый поиск по услугам — доработка небольшая.

## 5. Что готово и что доделать на сервере

**Готово (на живом с 24.10, по отчётам):**
- каталог товаров, карточка, разделы, главный экран, синхронизация;
- ремонт телефонов: услуги под модель, слоты, запись, мои записи;
- вход по паролю, профиль, выход;
- пересчёт корзины, заказ, мои заказы;
- тестовый режим.

**Доделать на сервере (новое):**
1. `GET /services/catalog` и `GET /services/catalog/{id}` — весь каталог услуг по направлениям.
2. `GET /search?q=` — единый поиск, два списка в одном ответе, параметр `type`.
3. `POST /services/requests` — заявка на выездную услугу (или решить, что услуги оформляются через корзину).
4. Поля у услуг в базе: тип (мастерская/выезд), гарантия, привязка к товарам/моделям — где их нет, добавить в админку.

**Уточнит серверная ветка:**
- заполнен ли `install_service_id` у товаров;
- есть ли эндпоинты избранного;
- какие поля услуг уже есть в базе, а каких нет;
- заявка на выезд: корзина или отдельный `/services/requests`.
